## 第 2 页｜一个看似简单的问题

### 页面标题

**一个看似简单的问题**

### 页面核心句

事实核查模型判断错了，究竟是：

**Verifier 不会判？**
还是
**Evidence 没有选对？**

### 页面正文

这两个错误来源在最终指标上会混在一起。
但它们对应的是完全不同的研究方向：

**如果是 verifier 的问题**：
重点应该放在更强模型、更好训练、更好 prompt。

**如果是 evidence 的问题**：
重点应该放在 retrieval、ranking、selector 和 evidence utility。

本项目后续所有实验，基本都围绕这条分解展开。

### 页面视觉建议

做成左右二分图：

```text
模型判断错了
     ↓
┌───────────────┬────────────────┐
│ Verifier Gap  │ Evidence Gap   │
│ 不会利用证据   │ 没看到好证据     │
└───────────────┴────────────────┘
```

可以在底部加一句小字：

```text
Same wrong prediction, different research diagnosis.
```

### 讲稿口播

“这个问题看起来很简单，但它决定了后面所有实验的方向。如果 verifier 本身不会判，那我们应该继续改验证模型；但如果 verifier 其实有能力，只是 selector 没有给它足够好的 evidence，那么继续堆 verifier 可能不会带来本质改善。所以这场分享会一直围绕这个诊断问题推进：错误到底来自判断模块，还是来自证据选择模块？”

## 第 3 页｜起点：Gold Evidence 并不自动好用

### 页面标题

**起点：Gold Evidence 并不自动好用**

### 页面核心句

数据集里标注为 evidence 的句子，
不一定就是当前 verifier 最需要的 evidence set。

### 页面正文

利用数据集内证据的探索性实验：

```text
LIAR-RAW is_evidence = 1
        ↓
取 top5 evidence
        ↓
微调 LLM verifier
        ↓
评估 fact-checking label
```

结果并不理想，换了不同的LLM（1.5/3/7B），不同的训练方法（SFT/GRPO），
或者换排序方法（按 hybrid score 重新排序/原始 sentence order），
使用原始标注证据 top5 的 test Macro-F1 都低于 重建证据后的 baseline。

### 页面指标表，建议保留精简版

| 方法                                 | 设置                            | Test Macro-F1 | 后续作用 |
| ---------------------------------- | ----------------------------- | ------------: | ------ |
| 原始证据 + 原始排序 | 标注 evidence 保留原始顺序            |         22.71 | 负向对照   |
| 原始证据 + hybrid order         | 标注 evidence 按 hybrid score 排序 |         23.51 | 负向对照   |
| 重建证据（hybrid score + MMR） | lambda=0.7, top_k=5           |     **27.69** | 固定基线   |

这些数值不是为了证明 gold evidence 没有价值，而是为了说明 **gold relevance label 不能直接替代 verifier utility**。

### 页面视觉建议

上半部分放流程图，下半部分放小表格。流程图建议简洁：

先 build 候选 evidence，再 train verifier，最后 infer 并保存指标；build 阶段会从 LIAR-RAW claims/reports 构造候选句子，并用 dense similarity、lexical overlap、BM25 与 MMR 做 evidence 处理，
所以这页可以自然承接到后面的 RAG/MMR 概念包。

右侧可以放一句醒目的诊断：

```text
Relevance ≠ Utility
```

“项目一开始并不是直接去设计复杂 selector，而是先尝试最自然的方案：既然 LIAR-RAW 里有 is_evidence=1 的句子级标注，那我们就直接把这些标注 evidence 取出来，作为 verifier 的输入。这个做法直觉上是合理的，因为它利用了人工 evidence label。但实验显示，这条路效果并不好。两种 raw evidence 排序方式的 Macro-F1 都低于 fixed-MMR baseline。这里的结论不是说 gold evidence 没有价值，而是说：人工标注的 evidence relevance，和当前 verifier 真正需要的 evidence utility，并不是同一个目标。”

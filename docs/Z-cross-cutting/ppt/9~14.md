## 第 10 页｜Claim-adaptive lambda 的直觉

### 页面标题

**Claim-adaptive lambda 的直觉**

### 页面核心句

不同 claim 需要的证据形态不同，
所以它们未必适合同一个 λ。

### 页面正文

一种 claim 可能需要：

```text
稠密、高相似、围绕关键事实的证据
→ 更高 λ
```

另一种 claim 可能需要：

```text
多来源、多角度、能限定或反驳的证据
→ 更低 λ
```

因此 learned-lambda 的问题不是“为了调参而调参”，而是：

```text
能否根据 claim 本身，预测它需要怎样的 evidence set？
```

### 页面视觉建议

左右两张 claim 卡片：

```text
Claim A
关键事实集中
需要高相似证据
λ ↑
```

```text
Claim B
信息分散
需要多角度证据
λ ↓
```

### 讲稿口播

“这一步的直觉是：不是所有 claim 都有同一种证据需求。某些 claim 的判断依赖一个集中的关键事实，这时更高 lambda 可能合理，因为我们希望证据紧贴 claim。另一些 claim 可能需要多来源、多角度的信息来限定语境，甚至需要包含反驳侧证据，这时过高相似度反而可能导致冗余。所以 learned-lambda 的真正问题是：能不能从 claim 的特征中预测它需要的证据选择策略？”

## 第 11 页｜Oracle lambda：先验证方向有没有价值

### 页面标题

**Oracle lambda：验证方向价值**

### 页面核心句

在训练 predictor 之前，先问一个上界问题：
**如果每个 claim 都能选到最优 λ，收益有多大？**

### 页面正文

做法：

```text
对每个 claim 枚举 21 个 λ
      ↓
每个 λ 生成一个 evidence set
      ↓
verifier 对 gold label 计算 logprob
      ↓
选 logprob 最高的 λ 作为 oracle λ
```

结果：

| 指标       | Fixed λ=0.70 | Oracle λ |       Δ |
| -------- | -----------: | -------: | ------: |
| Accuracy |        30.40 |    33.48 | +3.08pp |
| Macro-F1 |        30.60 |    33.84 | +3.24pp |

另外，48.4% 的样本在 oracle λ 和 fixed λ 下产生了不同 evidence 选择。
这说明 λ 确实改变 evidence set，也说明 adaptive λ 有理论价值。

### 页面视觉建议

左侧放 oracle 定义流程。
右侧放两个大数字：

```text
+3.08pp Acc
+3.24pp Macro-F1
```

底部放一句：

```text
Useful upper bound, but not a large one.
```

### 讲稿口播

“在真正训练 learned-lambda 之前，需要先确认这个方向有没有价值。所以这里先做 oracle lambda：对每个 claim 枚举多个 lambda，让每个 lambda 都生成 evidence set，再看 verifier 对 gold label 的 logprob，选择最优的那个。结果显示，相比 fixed lambda，oracle lambda 大约带来 3 个百分点的提升，而且接近一半样本的 evidence set 会变化。这说明 claim-adaptive lambda 不是空想，但它的上界也并不大。”

## 第 12 页｜Learned-lambda 实验链

### 页面标题

**Learned-lambda 实验链**

### 页面核心句

既然 oracle λ 有收益，下一步就是尝试把它学出来。

### 页面正文

尝试路线可以概括为四类：

```text
1. Hard predictor
   chunk embedding / 73 维手工特征 / classification

2. 修复 hard label
   high-margin 过滤 / 3-bin 粗分类

3. 软化策略
   soft-label λ policy / sensitivity-gated MMR

4. 偏好学习
   DPO step-wise λ
```

这些实验共同试图回答一个问题：

```text
能不能从 claim 与候选 evidence 的可见特征中，
稳定预测一个有用的 λ？
```

### 页面视觉建议

做成横向实验路线图：

```text
Oracle λ
   ↓
Hard predictor
   ↓
High-margin / 3-bin
   ↓
Soft-label / gated MMR
   ↓
DPO step-wise λ
```

每个节点下方只放 1–2 个关键词。

### 讲稿口播

“接下来就是 learned-lambda 实验链。最直接的做法是把 oracle lambda 当成标签，用 claim embedding、chunk embedding 或手工特征去预测。发现不稳后，又尝试了 high-margin 过滤和 3-bin 粗分类，试图减少标签噪声。再往后，把 hard label 改成 soft-label policy，或者用 sensitivity gate 判断是否值得调整 lambda。最后还试过 DPO 式的 step-wise lambda。也就是说，这里并不是只试了一个预测器，而是沿着 hard label、soft label、preference learning 都试了一轮。”

## 第 13 页｜为什么 learned-lambda 学不动

### 页面标题

**为什么 learned-lambda 学不动**

### 页面核心句

失败不主要是模型太小，
而是 λ 的监督信号太弱、表达空间太窄。

### 页面正文

关键观察：

```text
R² ≈ 0.01
predictor 基本接近均值预测
```

```text
72.6% 样本
最优 λ 与次优 λ 的 margin < 0.05
```

```text
soft-label utility curve 接近均匀
expected λ 退化为 fixed
```

```text
DPO step-wise 四轮训练
最终坍缩到 λ = 0.7
```

因此 oracle λ 更像一个不稳定 hard label：

```text
很多 claim 的 λ utility curve 很平，
“最优 λ” 和 “次优 λ” 的差异太小。
```

这些失败信号在大纲中被归纳为：监督信号太弱，scalar λ 表达太窄，而不是简单地“模型还不够强”。

### 页面视觉建议

用三块大数字：

```text
R² ≈ 0.01
72.6% margin < 0.05
DPO → λ = 0.7
```

底部放结论：

```text
Weak supervision, narrow control space.
```

### 讲稿口播

“失败原因不应简单归结为模型不够大。核心问题是 oracle lambda 这个监督信号本身很弱。很多样本上，最优 lambda 和次优 lambda 的差距非常小，所以 hard label 本身不稳定。预测器自然会向均值收缩。soft-label 看起来更平滑，但 utility curve 又接近均匀，最后 expected lambda 也退化回 fixed。DPO 也没有学出稳定策略，最后坍缩到 0.7。到这里基本可以判断，继续堆 learned-lambda 的收益空间很有限。”

## 第 14 页｜Lambda 方向收尾

### 页面标题

**Lambda 方向收尾**

### 页面核心句

Oracle λ 证明方向有价值；
learned λ 证明它不值得作为主线继续做。

### 页面正文

这条路线的结论可以分成两半：

```text
Go:
oracle λ 比 fixed λ 有约 +3pp 上界
说明 claim-adaptive 权衡确实存在价值
```

```text
Stop:
可学习信号不足
soft-label / gated / DPO 都没有形成稳定可部署策略
单个 scalar λ 只能沿 MMR 的一维旋钮移动
```

因此主线不再继续问：

```text
λ 应该取多少？
```

而是转向：

```text
哪一组 evidence 最能帮助 verifier 做对？
```

### 页面视觉建议

做成 Stop / Go 决策表：

| 发现               | 判断                 | 下一步                       |
| ---------------- | ------------------ | ------------------------- |
| oracle λ 有约 +3pp | Go as diagnostic   | 说明 adaptive selection 有价值 |
| learned λ 学不稳    | Stop as main route | 不继续预测单个 scalar            |
| λ 只是一维旋钮         | Pivot              | 转向 evidence set utility   |

### 讲稿口播

“所以 lambda 方向的收尾不是完全失败，而是一个有用的诊断。oracle lambda 证明了 claim-adaptive 的证据选择确实有收益；但 learned-lambda 系列说明，这个收益很难通过预测单个 scalar lambda 稳定拿到。更重要的是，lambda 只能在 MMR 已经定义好的相关性和去冗余之间移动，它不能直接表达一组 evidence 对 verifier verdict 的贡献。因此下一步自然转向 evidence set：不再问 lambda 取多少，而是问哪一组 evidence 最有用。”

---

第 14 页到第 15 页的过渡句建议用这一句：

```text
到这里，lambda 已经完成了它的诊断作用：
它告诉我们 evidence selection 有空间，
但真正的空间不在一维旋钮上，而在 evidence set utility 上。
```

Q: 第一份aaai_fact_checking[docs/Z-cross-cutting/aaai_fact_checking_method_upgrade.md]文件时之前提出的一版fc方法，现在我把它升级到了第二份文件[docs/G-map_selectors-upgrade/20260619_atom_fact_anchored_qec_method_overview.md]所给出的方法，请帮我分析新版方法若要去AAAI投稿可能面临的局限性，并帮我规划一版详细的消融实验


## 总体判断

新版明显强于旧版。旧版的核心仍是“结构化 evidence map + typed graph + 规则式 selector”，且 graph 信息并未进入 verifier；新版则增加了 ABC claim-aware chunking，将规则选择器改写为 budgeted marginal selection，并通过 `qec_min/qec_map` 将问题或 atom 对齐信息显式暴露给 verifier。也就是说，新版已经从“上游证据筛选器”转向“证据单元构造—结构化选择—提示渲染”的完整证据组织方法。 

不过，以 AAAI 主技术轨的标准看，新版目前仍存在三个一级风险：

1. **与最新相关工作的贡献边界过近，尤其是 KG-CRAFT。**
2. **QEC 和 graph 的实际增益尚未被当前结果证明，且存在 shortcut learning 风险。**
3. **实验协议中出现 test checkpoint diagnostics，若处理不严会构成严重的 test leakage。**

AAAI-27 的评审标准明确强调 significance、novelty、soundness、clarity 和 reproducibility，并不偏好仅在狭窄 benchmark 上做增量改进；正文只有 7 页，关键方法和实验不能依赖审稿人阅读补充材料。([AAAI][1])

# 一、新版方法面临的主要局限

## 1. 最大风险：方法可能被评价为现有模块的组合

新版方法包含：

* claim-aware chunking；
* question decomposition retrieval；
* atomic claim decomposition；
* evidence map；
* typed evidence graph；
* budgeted subset selection；
* question-guided prompting；
* label-token verifier。

每个模块单独看都合理，但相关方向已经比较拥挤：

* QACheck 已使用 question-guided、multi-hop fact-checking；
* ProgramFC、动态 claim decomposition 和 FactLens 已讨论 claim/subclaim decomposition；
* GraphCheck 已使用 entity-relation graph 和自适应推理路径；
* Minimal Evidence Group Identification 已直接形式化“最小证据组”问题；
* User-Centric Evidence Ranking 已研究 sufficiency、complementarity 和 redundancy-aware evidence ranking。([aclanthology.org][2])

更关键的是，EACL 2026 的 KG-CRAFT 在 **LIAR-RAW 和 RAWFC 这两个相同数据集**上构建 claim/report knowledge graph、生成 contextually relevant contrastive questions、蒸馏 evidence summary 并预测标签，与 AA-QEC 的“graph → question cue → evidence organization → verdict”非常接近。([aclanthology.org][3])

因此，不能仅把论文贡献概括为：

> atom + graph + question-guided evidence chain。

这个表述容易被认为是对已有技术的集成。建议把唯一主贡献收窄为：

> **在真实 evidence text 不被摘要替代的条件下，对 atom-aligned evidence 进行 token-budgeted、coverage–redundancy-aware subset selection。**

也就是强调三个差异：

* 选择的是原始证据，而非生成式 summary；
* 预算单位是 verifier token，而非 passage 数量；
* 优化对象是 atom coverage、evidence complementarity 和 redundancy 的联合效用。

ABC chunker 和 QEC prompt 应暂时作为辅助组件，而不是并列的三项核心创新。

---

## 2. “optimization”形式化仍然可能被视为启发式加权打分

新版将旧版 P1/P2/P3 规则改成了：

[
e_t=\arg\max_{e\notin S}\Delta F(e\mid S)
]

这是重要升级，但目前的目标函数依然由手工权重组合：

[
F(S)=
\lambda_{\rm cov}F_{\rm cov}
+\lambda_{\rm map}F_{\rm map}
+\lambda_{\rm base}F_{\rm ret}
+\lambda_{\rm edge}F_{\rm graph}
-\lambda_{\rm dup}F_{\rm dup}
-\lambda_{\rm bg}F_{\rm bg}
-\lambda_{\rm len}|S|.
]



审稿人可能继续追问：

* 每个 (\lambda) 如何得到？
* 为什么 complements、corroborates 和 tension 都应获得正效用？
* 为什么 pairwise coherence 与 atom coverage 的量纲可直接相加？
* adaptive stopping 的 (\epsilon) 是否仅在 test 上调优？
* 不同数据集为什么需要不同 tightness policy？

这里还有一个理论问题：

* atom coverage 通常是 submodular 的；
* retrieval/map quality 是 modular 的；
* redundancy penalty 可产生 diminishing return；
* 但正向 pairwise coherence，例如
  [
  \sum_{(e_i,e_j)\in G[S]}\psi(e_i,e_j),
  ]
  往往具有 increasing return，属于 supermodular 成分。

因此整个目标通常既不保证 monotonicity，也不保证 submodularity，普通 greedy selection 没有标准近似保证。

可选的补救方案是：

1. 将 pairwise coherence 改写为 concave neighborhood coverage 或 facility-location utility，使目标尽可能保持 submodular；
2. 在 (N=20) 的候选池上增加 ILP/exhaustive beam oracle，对比 greedy 与近似最优解；
3. 不宣称理论最优，明确称为 graph-aware marginal heuristic，并通过 strong oracle-gap analysis 证明 greedy 足够接近最优；
4. 学习 (\lambda)，而不是手工指定。可用 validation ranking loss、listwise loss 或 verifier utility 作为训练信号。

---

## 3. passage 数量预算不等于真实 verifier 预算

新版仍以 (k_{\min},k_{\max}) 控制 evidence 数量，但 ABC chunk 是变长的。5 个短句和 5 个长 chunk 对 verifier 的 token 成本可能相差很大。

因此：

[
|S|\leq k
]

不是公平的上下文预算。建议改成：

[
\sum_{e\in S}\operatorname{TokLen}(e)\leq B_{\rm tok}.
]

长度惩罚也应改为：

[
\lambda_{\rm len}\sum_{e\in S}\operatorname{TokLen}(e),
]

而不是 (\lambda_{\rm len}|S|)。

否则 ABC 可能只是通过产生更长或更短的 chunk 获得不公平优势。主实验至少应固定：

[
B_{\rm tok}\in{512,1024,2048}.
]

并报告 Macro-F1–token cost Pareto curve。

---

## 4. 当前方法未必真正构成“chain”

如果 selector 只是按 marginal gain 依次选择一个 evidence subset，那么它首先是一个**有序集合**，不天然是 evidence chain。

“Chain”通常隐含：

* 当前步骤依赖前一步；
* evidence 间存在显式的连接或推理关系；
* 顺序变化会影响推理结果；
* 每一步解决上一步遗留的未覆盖 atom 或问题。

当前方法虽然输出 `role/check/evidence/map`，但若没有连接约束：

[
e_t \rightarrow a_i \rightarrow e_{t+1},
]

或者没有 step dependency，审稿人可能质疑只是将 ranked evidence list 重新命名为 chain。

解决方式有两种：

* 保守做法：改称 **Atom-Aligned Evidence Set/Ranking**；
* 强化做法：定义 chain connectivity，例如每个 (e_t) 必须满足：
  [
  \operatorname{newAtom}(e_t,S_{t-1})>0
  \quad\text{或}\quad
  \exists e_j\in S_{t-1}:(e_j,e_t)\in E_{\rm valid}.
  ]

同时做 evidence order shuffle 实验。若顺序打乱后性能几乎不变，则不宜把“chain reasoning”作为主张。

---

## 5. QD questions 与 claim atoms 是两套独立分解，可能发生语义错配

新版中：

* QD question 用于 retrieval；
* claim atoms 用于 evidence map；
* `check_t` 优先采用 QD question，其次才使用 covered atom。

但目前没有显式保证：

[
q_i \leftrightarrow a_j \leftrightarrow e_k
]

三者语义一致。

可能出现：

* QD question 询问时间，evidence 实际覆盖数量；
* evidence map 标为 support，但 QD question 带有否定预设；
* 一个 question 对应多个 atoms；
* 一个 atom 被多个语义重复的 questions 覆盖；
* fallback check cue 与 evidence 实际内容不匹配。

建议显式构建 question–atom alignment：

[
H_{ij}=P(a_j\text{ is addressed by }q_i),
]

并在选择 chain step 时要求：

[
\operatorname{check}(e)
=======================

\arg\max_{q_i,a_j}
H_{ij}\cdot P(e\text{ covers }a_j).
]

至少应在人工标注子集上评估：

* QD question–atom alignment F1；
* check cue–evidence consistency；
* check cue hallucination rate；
* question redundancy；
* uncovered atom rate。

---

## 6. `qec_map` 存在明显的 label shortcut 风险

`qec_map` 暴露：

```text
relation=support/refute/qualify/mixed
directness=direct/partial/context
```

这些标签已经非常接近 verifier 要预测的 truthfulness orientation。尤其在 RAWFC 三分类中，模型可能不再真正阅读 evidence，而是直接将：

* support → true；
* refute → false；
* qualify/mixed → half。

因此，即便 mapper 从未看到 gold label，`relation` 仍然相当于一个上游 pseudo-label。性能提高可能来自“读取 annotation”，而不是 evidence reasoning。

这是新版新增的、非常容易被审稿人攻击的问题。必须增加以下控制：

| 控制实验                       | 目的                                       |
| -------------------------- | ---------------------------------------- |
| Tag-only，去掉 evidence text  | 测试标签是否几乎能从 map tags 直接预测                 |
| Shuffled relation tags     | 测试模型是否依赖 relation 字段                     |
| Randomized atom IDs        | 测试 atom 编号是否只是格式信号                       |
| `qec_map` without relation | 隔离 coverage/directness 与 stance shortcut |
| Wrong check cue            | 测试 cue 对 verifier 的诱导程度                  |
| Evidence-only plain        | 判断真正 evidence text 的贡献                   |
| Evidence order shuffled    | 判断所谓 chain order 是否有效                    |

若 Tag-only 的 Macro-F1 明显高于 claim-only，或者 shuffled relation 造成大幅下降，就必须把 `relation` 从主 prompt 中移除，只用于 selector。

## 7. 当前结果并未证明 `qec_map` 是有效贡献

新版记录中：

* LIAR-RAW `qec_map` Macro-F1 = 0.3587；
* LIAR-RAW `qec_min` Macro-F1 = 0.3578。

差值只有：

[
0.3587-0.3578=0.0009,
]

即 **0.09 个百分点**。同时 `qec_map` 的 selection 指标反而低于 `qec_min`。

这个幅度在没有多随机种子和置信区间时基本不能视为实质增益。因此当前最稳妥的论文处理是：

* 主方法使用 `qec_min`；
* `qec_map` 放入 prompt sensitivity；
* 除非 3–5 个随机种子后仍有稳定显著收益，否则不要把 map-aware prompting 写成主贡献。

新版文件中将二者视为同一 selector 的两种 prompt realization，这个定位是正确的。

## 8. 与相同数据集上的强基线存在较大压力

KG-CRAFT 在 LIAR-RAW 和 RAWFC 上报告了多种 backbone 的结果。其 LIAR-RAW F1 约为 60.99–73.87，RAWFC F1 约为 66.67–81.58。

你的当前记录是：

* LIAR-RAW：约 35.8 Macro-F1；
* RAWFC：约 67.2 Macro-F1。

不能直接断言这些数值可严格横向比较，因为 backbone、split、训练方式和 F1 定义可能不同。但从审稿角度看，仍然会出现两个问题：

1. LIAR-RAW 上为何与公开强方法有明显差距？
2. 新方法是否只是用较小模型换取了效率？

第二个问题反而可以成为论文机会。应将贡献定位为：

> 用较小 verifier、较少 evidence tokens 和可追踪原始证据，达到有竞争力的性能。

但必须报告：

* 同一 Qwen2.5-7B verifier 下的 KG-CRAFT-style baseline；
* 同一 token budget；
* 同一 candidate reports；
* 同一 split；
* 同一训练数据；
* 每样本 LLM calls、input tokens、latency 和 GPU-hours。

DeReC 在相同数据方向上报告了 RAWFC F1 65.58，并强调了显著的运行效率提升，因此效率基线不能缺失。([aclanthology.org][4])

## 9. test checkpoint diagnostics 是必须立即修正的实验协议问题

新版记录中写到：

> 保留 val-best alias 作为官方选择，但直接查看 test diagnostics 后，checkpoint-400 的 test 表现更好。



只要最终报告或方法选择受到 test diagnostics 影响，就构成 test-set peeking。即使没有显式用 test 调参，审稿人看到这段描述也会质疑整个实验流程。

正式实验必须执行：

1. 仅使用 validation 选择 checkpoint、超参数、prompt 和 dataset-specific policy；
2. 冻结所有决策；
3. test 只运行一次正式评估；
4. 不报告“我们检查的 test checkpoints 中某个更好”；
5. 若 test 已被反复查看，建议重新构造 untouched test subset，或者至少使用多个随机划分并明确说明限制。

这一点优先级高于继续增加新模块。

## 10. 两个数据集使用不同 policy，可能被认为过度 dataset engineering

新版中：

* LIAR-RAW 使用 ABC、`qec_min/qec_map`；
* RAWFC 使用 rawfc-tight、anchor-only、`qec_min`。

这在工程上可能合理，但审稿人会问：

* tight threshold 是否根据 test 调过？
* 为什么同一方法不能统一？
* policy 是由数据规模、平均报告长度还是标签数决定？
* 换一个新数据集后如何自动选择 policy？

建议至少增加：

| 实验                                   | LIAR-RAW | RAWFC |
| ------------------------------------ | -------: | ----: |
| Standard ABC + full evidence         |        ✓ |     ✓ |
| Tight ABC + anchor-only              |        ✓ |     ✓ |
| 自动 policy，由 validation complexity 选择 |        ✓ |     ✓ |

如果 tight 只在 RAWFC 有效，需要进一步证明它与可观测数据属性相关，例如平均 report 长度、背景比例、候选冗余度，而不是数据集名称。

## 11. 当前任务属于 bounded associated-report verification，外部有效性有限

LIAR-RAW 和 RAWFC 使用与 claim 关联的 raw reports，任务重点是从 bounded report collection 中筛选证据，而不是从开放网页完成完整检索。原始 CofCED 工作本身也将问题建模为在 raw reports 中级联选择证据。([aclanthology.org][5])

因此论文不宜笼统声称解决了 realistic automated fact-checking。更准确的任务定义是：

> evidence organization and fine-grained verdict prediction over claim-associated raw reports。

同时应审计：

* report 发布时间与 claim 时间；
* 同源转载与 syndicated duplicates；
* claim 本身是否被报告直接重复；
* report 是否发布于 fact-check verdict 之后；
* report 是否包含结论性或标签式措辞。

至少增加一个外部评估。AVeriTeC 较适合，因为它同时评估 verdict 和 evidence quality，只有证据质量达到一定条件时，正确 verdict 才能获得联合得分。([aclanthology.org][6])

---

## 12. claim-aware chunking 的可扩展性和公平性尚未证明

ABC chunking 是 query-dependent 的：

[
B_i=w_{\rm sem}(1-\operatorname{sim}(s_i,s_{i+1}))
+w_{\rm rel}|rel(s_i,c)-rel(s_{i+1},c)|.
]

这意味着同一篇 report 对不同 claim 可能需要重新切分。

在 bounded report 场景中成本可控，但开放检索中存在问题：

* 无法完全离线预索引；
* 每个 claim 需要额外 embedding/scoring；
* chunk boundaries 可能利用 claim lexical cues，获得对普通 chunk baseline 不公平的优势；
* query-specific segmentation 可能把与 claim 不一致但语义相关的句子切掉。

因此 ABC 的比较必须在固定 token budget、固定 embedding model 和相同 preprocessing cost 下进行，并报告每 claim 的额外耗时。

---

## 13. fine-grained 六分类与当前 verifier 目标不完全匹配

LIAR-RAW 标签具有天然序关系：

[
\text{pants-fire}
<
\text{false}
<
\text{barely-true}
<
\text{half-true}
<
\text{mostly-true}
<
\text{true}.
]

但 label-token cross entropy 把六个标签当作无序类别。把 `pants-fire` 误判为 `true` 和误判为 `false` 在 CE 中受到的类别距离惩罚相同。

如果论文强调 fine-grained verification，建议至少增加：

* ordinal MAE；
* quadratic weighted kappa；
* adjacent-error rate；
* severe-error rate，即距离至少 3 个标签等级；
* CE 与 CE + ordinal loss 的消融。

这不一定要成为主方法，但可以避免“fine-grained 只体现在数据标签上”的质疑。

# 二、消融实验的总体原则

在具体实验前，先固定四条协议。

## 协议 A：上游模块和 verifier 必须解耦

建立两套评估：

**Selection-only protocol**

* 固定 candidate pool；
* 固定 evidence map；
* 固定 verifier；
* 仅替换 selector；
* 评估 intrinsic selection quality 和 frozen-verifier performance。

**End-to-end protocol**

* 对最终 4–6 个核心变体分别重新训练 verifier；
* 相同随机种子；
* 相同训练步数和 early-stopping protocol；
* 测量可达到的最终性能。

前者用于因果归因，后者用于最终性能。

## 协议 B：统一 token budget

所有 evidence 方法必须满足相同：

[
\sum_{e\in S}\operatorname{TokLen}(e)\leq B.
]

不要仅统一 top-(k)。建议：

[
B\in{512,1024,2048}.
]

## 协议 C：所有 LLM 中间标注必须缓存

Question decomposition、atom decomposition、relation/directness 和 graph edges 必须：

* 使用固定模型版本；
* temperature = 0 或固定采样种子；
* 保存完整 prompts 和 outputs；
* 不允许 mapper 看到 gold label；
* 不因不同 selector 重复生成不同 map。

## 协议 D：validation-only model selection

所有 checkpoint、(\lambda)、(\epsilon)、tightness、prompt style 均只由 validation 确定。

# 三、主论文建议采用的“因果阶梯”消融

该表应成为主论文的核心表。A0–A9 一律使用 plain evidence prompt，先隔离 evidence pipeline；A10–A11 再测试 QEC rendering。

| ID  | 变体                                   | 相比上一行增加的模块                 | 主要回答的问题                         |
| --- | ------------------------------------ | -------------------------- | ------------------------------- |
| A0  | Claim-only verifier                  | 无 evidence                 | 数据本身是否存在 claim-only label prior |
| A1  | Full reports truncated to (B) tokens | 原始上下文                      | selector 是否确有必要                 |
| A2  | Sentence units + hybrid top-(B)      | 基础 retrieval               | 普通检索基线                          |
| A3  | A2 + MMR                             | diversity                  | 多样性是否有效                         |
| A4  | A3 + QD retrieval union              | question routes            | QD 是否增加重要 atom recall           |
| A5  | A4 + ABC chunking                    | claim-aware units          | ABC 的独立贡献                       |
| A6  | A5 + map-quality ranking             | evidence map               | 结构化 map 是否优于 retrieval score    |
| A7  | A6 + atom-coverage greedy            | coverage-aware subset      | atom coverage 是否是主要机制           |
| A8  | A7 + typed graph terms               | complement/conflict/bridge | graph 是否提供额外价值                  |
| A9  | A8 + adaptive token stopping         | adaptive budget            | 是否能以更少 tokens 保持性能              |
| A10 | A9 + `qec_min`                       | check cue                  | question cue 是否有效               |
| A11 | A9 + `qec_map`                       | compact map tags           | map metadata 是否额外有效             |

主结论必须来自以下差值：

[
\Delta_{\rm ABC}=A5-A4
]

[
\Delta_{\rm Map}=A6-A5
]

[
\Delta_{\rm Atom}=A7-A6
]

[
\Delta_{\rm Graph}=A8-A7
]

[
\Delta_{\rm Stop}=A9-A8
]

[
\Delta_{\rm QECmin}=A10-A9
]

[
\Delta_{\rm QECmap}=A11-A9.
]

若 (A8-A7) 不显著，则 typed graph 不应作为核心贡献；若 (A10-A9) 不显著，则 QEC 只应视为格式设计。

# 四、模块级详细消融

## 4.1 ABC evidence unit 消融

| ID | Evidence unit                          |
| -- | -------------------------------------- |
| U0 | sentence                               |
| U1 | fixed 128-token windows                |
| U2 | fixed 256-token windows                |
| U3 | generic semantic chunking              |
| U4 | ABC without claim relevance term       |
| U5 | ABC without semantic boundary term     |
| U6 | full ABC                               |
| U7 | full ABC tight                         |
| U8 | oracle human sentence boundaries，小规模子集 |

固定 retrieval 和 selector，报告：

* candidate evidence recall；
* important atom recall；
* evidence precision；
* average unit tokens；
* units per report；
* retrieval latency；
  -最终 Macro-F1。

关键假设是：

> ABC 应在相同总候选 token 数下，提高重要 atom recall，而不是仅通过生成更多或更长的单位获得优势。

## 4.2 Claim/QD retrieval 消融

| ID | Route                                      |
| -- | ------------------------------------------ |
| R0 | claim-only dense                           |
| R1 | claim-only BM25                            |
| R2 | claim-only hybrid                          |
| R3 | claim-only hybrid + MMR                    |
| R4 | QD-only                                    |
| R5 | claim + QD union                           |
| R6 | union without RRF                          |
| R7 | union without question-hit-count feature   |
| R8 | union with random questions                |
| R9 | union with human questions，小规模 upper bound |

重点指标：

[
\operatorname{AtomRecall@B}
===========================

\frac{\sum_a w_a\mathbf 1[\exists e\in C_B:e\text{ covers }a]}
{\sum_a w_a}.
]

如果 QD union 仅提高普通 evidence recall，却不提高 important atom recall，其方法价值会较弱。

## 4.3 Evidence map 字段消融

从 full map 做 remove-one：

| ID  | 变体                          |
| --- | --------------------------- |
| M0  | no map，retrieval score only |
| M1  | atom coverage only          |
| M2  | M1 + directness             |
| M3  | M2 + relation               |
| M4  | M3 + confidence             |
| M5  | M4 + key spans              |
| M6  | M5 + duplicate group        |
| M7  | full map − relation         |
| M8  | full map − directness       |
| M9  | full map − confidence       |
| M10 | full map − key spans        |
| M11 | full map − duplicate group  |
| M12 | full map                    |

这里同时需要一组 map quality 实验：

* LLM-induced map；
* cross-model-induced map；
* human-checked map；
* randomized map；
* noisy map。

建议人工标注约 300–400 个样本，并覆盖：

* 单 atom / 多 atom；
* support / refute / qualify；
* 有冲突 / 无冲突；
* 短 report / 长 report。

人工评估：

* atom boundary F1；
* evidence–atom link F1；
* relation Cohen’s (\kappa)；
* directness (\kappa)；
* duplicate-group pairwise F1；
* key-span overlap F1。

## 4.4 Graph edge 和目标函数消融

| ID  | 目标函数                      |
| --- | ------------------------- |
| G0  | retrieval utility only    |
| G1  | G0 + atom coverage        |
| G2  | G1 + complements          |
| G3  | G2 + corroborates         |
| G4  | G3 + duplicate penalty    |
| G5  | G4 + bridge context       |
| G6  | G5 + tension              |
| G7  | G6 + background penalty   |
| G8  | full graph objective      |
| G9  | full − complements        |
| G10 | full − corroborates       |
| G11 | full − bridge             |
| G12 | full − tension            |
| G13 | full − duplicate penalty  |

`tension` 应特别独立测试，因为“存在冲突”不等于“该冲突有验证价值”。还应按 conflict type 分层：

* temporal tension；
* numerical tension；
* source disagreement；
* scope mismatch；
* definition mismatch；
* low-credibility conflict。

如果 tension 只在少量样本有效，建议将其作为条件性 utility：

[
\psi_{\rm tension}(e_i,e_j)
===========================

\mathbf 1[\operatorname{credible}(e_i,e_j)]
\cdot w_{\rm tension},
]

而不是所有 tension edge 都加分。

## 4.5 Selector 算法消融

| ID  | Selector                                          |
| --- | ------------------------------------------------- |
| S0  | retrieval top-(B)                                 |
| S1  | MMR                                               |
| S2  | map-quality top-(B)                               |
| S3  | weighted set cover over atoms                     |
| S4  | Minimal Evidence Group / set-cover-style baseline |
| S5  | fixed-budget marginal greedy                      |
| S6  | adaptive marginal greedy                          |
| S7  | beam search                                       |
| S8  | ILP optimum，限 (N\leq20)                           |
| S9  | LLM-as-selector                                   |
| S10 | random subset，匹配长度分布                              |
| S11 | AA-QEC selector                                   |

ILP/beam 的主要作用不是成为最终方法，而是测量 greedy optimality gap：

[
\operatorname{Gap}
==================

\frac{F(S_{\rm oracle})-F(S_{\rm greedy})}
{|F(S_{\rm oracle})|+\varepsilon}.
]

如果 greedy 与 ILP 几乎相同，可以支撑效率选择；若差距很大，应重新设计目标或搜索算法。

## 4.6 Adaptive stopping 消融

比较：

* fixed 512 tokens；
* fixed 1024 tokens；
* fixed 2048 tokens；
* fixed (k=3,5,7,10)；
* adaptive passage-count stopping；
* adaptive token-cost stopping。

敏感性范围：

[
\epsilon\in
{0,;0.01,;0.02,;0.05,;0.1}
]

或按 validation marginal-gain 分位数设定。

应画两条曲线：

1. Macro-F1 vs average selected tokens；
2. Important atom coverage vs average selected tokens。

adaptive stopping 的理想结论不是“F1 最高”，而是：

> 在保持相近 F1 的情况下，显著减少 evidence tokens。

# 五、QEC prompt 必须开展的 shortcut controls

这一组应列入主文或至少主文引用，不宜全部放补充材料。

| ID  | Prompt                            |
| --- | --------------------------------- |
| P0  | plain evidence list               |
| P1  | `qec_min`，QD check cue            |
| P2  | atom cue only                     |
| P3  | QD cue only                       |
| P4  | `qec_map` without relation        |
| P5  | full `qec_map`                    |
| P6  | shuffled check cues               |
| P7  | shuffled relation/directness tags |
| P8  | random atom IDs                   |
| P9  | tag-only，remove evidence text     |
| P10 | evidence-only，remove all cues     |
| P11 | reverse evidence order            |
| P12 | random evidence order             |
| P13 | adversarial wrong cue             |

需要分别回答：

1. `qec_min` 是否真的帮助 evidence–question alignment？
2. `qec_map` 是否主要依赖 relation pseudo-label？
3. evidence order 是否构成真实 chain？
4. cue 错误时模型是否盲从？
5. cue 在不同 verifier 上是否可迁移？

最关键的判据是：

[
\operatorname{F1}(P5)

>

\operatorname{F1}(P4)
]

并不足以证明 relation 有效；还要同时满足：

[
\operatorname{F1}(P9)\approx\operatorname{F1}(P0_{\rm claim-only}),
]

否则存在 map tag shortcut。

# 六、证据充分性、必要性和鲁棒性实验

只报告最终 Macro-F1 无法证明“最小充分 evidence chain”。

## 6.1 Sufficiency

比较：

* selected chain；
* top-(B) retrieval；
* all top-20 candidates；
* random matched-length evidence；
* map-quality top-(B)；
* human sufficient subset。

定义：

[
\operatorname{SuffGain}
=======================

## \operatorname{Perf}(c,E^*)

\operatorname{Perf}(c).
]

还可以测量 gold-label probability preservation：

[
\operatorname{SuffError}
========================

## P(y\mid c,C_{\rm all})

P(y\mid c,E^*).
]

数值越接近 0，selected chain 越接近完整 candidate context。

## 6.2 Necessity / comprehensiveness

移除：

* marginal gain 最大的 evidence；
* 覆盖最高重要性 atom 的 evidence；
* primary role evidence；
* secondary evidence；
* bridge evidence。

定义：

[
\operatorname{NecDrop}
======================

## P(y\mid c,E^*)

P(y\mid c,E^*\setminus E_{\rm key}).
]

如果移除所谓 primary evidence 后几乎无变化，说明 chain 中的“关键证据”并不必要。

## 6.3 Insertion curve

按 selector 顺序逐条加入 evidence：

[
E_1\subset E_2\subset\cdots\subset E_T.
]

画：

[
P(y\mid c,E_t)
\quad\text{或}\quad
\operatorname{Accuracy}(E_t)
]

随 (t) 或 token 数变化的曲线，并计算 AUC。好的 evidence ranking 应更早达到较高性能，这与 user-centric evidence ranking 的目标一致。([aclanthology.org][7])

## 6.4 Distractor robustness

添加以下 distractors，数量设为 1、3、5：

* high lexical overlap but irrelevant；
* same-topic background；
* duplicate paraphrases；
* low-credibility conflict；
* temporally outdated evidence；
* evidence supporting another atom but not current check；
* claim-repetition sentence。

定义：

[
\operatorname{RobustDrop}
=========================

## \operatorname{F1}(E^*)

\operatorname{F1}(E^*\cup D).
]

同时测试 distractors 是在 selector 前加入 candidate pool，还是在 selector 后直接加入 verifier，两者分别对应 selection robustness 和 verifier robustness。

# 七、跨 verifier 与跨数据集实验

## 7.1 Cross-verifier transfer

固定同一 evidence chain，至少测试：

* Qwen2.5-1.5B；
* Qwen2.5-7B；
* 一个不同模型家族的 7B–8B verifier；
* 冻结 instruction model；
* LoRA fine-tuned verifier。

主要观察：

[
\Delta_v
========

## \operatorname{F1}*v(E*{\rm AAQEC})

\operatorname{F1}*v(E*{\rm top-k}).
]

如果 selector 只对训练它时使用的 Qwen verifier 有效，则方法可能是 verifier-specific prompt engineering；如果多个 verifier 均受益，才能证明 evidence selection 本身有效。

## 7.2 Cross-dataset policy transfer

至少执行：

* LIAR-RAW validation 上确定的参数直接用于 RAWFC；
* RAWFC 参数直接用于 LIAR-RAW；
* unified policy；
* dataset-specific policy。

如果 dataset-specific policy 显著更好，需要明确其依据并报告额外自由度。

## 7.3 外部数据集

优先建议 AVeriTeC，因为其评估同时关注 evidence quality 和 verdict；其次可考虑 HoVer、FEVEROUS 或 SciFact。([aclanthology.org][6])

不一定需要完整重新训练。可以做：

* zero-shot chain selection；
* frozen verifier；
* 500–1000 个样本的 controlled transfer；
* evidence selection intrinsic evaluation。

# 九、统计检验与随机种子

建议：

* 所有训练型最终结果至少 3 个 seeds；
* 主方法和最强 baseline 使用 5 个 seeds；
* 报告 mean ± standard deviation；
* Macro-F1 使用 paired bootstrap，至少 10,000 次重采样；
* 报告 95% confidence interval；
* 多个 ablation 与 full model 比较时使用 Holm correction；
* 同时报告绝对增益和相对误差降低；
* 0.5 个百分点以内的增益，若置信区间重叠，不应写成稳定提升。

尤其是当前 `qec_map` 与 `qec_min` 的 0.09 个百分点差异，应默认视为未证明，直到多 seed 统计结果出现。

# 十一、复杂度分层分析

整体平均分可能掩盖 graph 和 atom 的真实作用。建议按以下维度分桶：

* atom 数量：1、2、≥3；
* evidence hops：single-hop、multi-hop；
* conflict：无冲突、有冲突；
* claim 类型：numeric、temporal、comparative、causal、attribution；
* report 长度四分位；
* candidate redundancy 四分位；
* selected chain tokens；
* source 数量。

预期机制应该是：

* ABC 在长 report 和背景比例高的样本上更有效；
* QD 在多 atom claim 上提高 recall；
* graph selector 在 ≥3 atoms 和 multi-hop 样本上效果更明显；
* duplicate penalty 在高冗余样本上有效；
* bridge context 在需要定义或时间背景的样本上有效；
* tension 在真实冲突样本上有效，而非全体样本。

若 graph 在单 atom 和多 atom样本上的增益没有差别，或者在复杂 claim 上也没有额外改善，则 graph-aware reasoning 的机制主张会比较薄弱。

# 十二、建议的投稿定位

当前不建议以以下表述作为标题或主贡献：

> Minimal Sufficient Evidence Chain Selection

因为：

* “minimal”尚未通过 token-budget、oracle 或 necessity 实验验证；
* “sufficient”尚未通过 sufficiency evaluation 验证；
* “chain”尚未证明顺序或连接结构必要；
* minimal evidence group 已有非常接近的正式定义。([aclanthology.org][8])

现阶段更稳妥的标题是：

> **Token-Budgeted Atom-Aligned Evidence Selection for Fine-Grained Fact Verification**

或者：

> **Atom-Aligned Evidence Organization under Verifier Budgets for Fine-Grained Fact-Checking**

论文贡献建议压缩成三点：

1. 提出 token-budgeted atom-aligned evidence selection，在原始 evidence text 上联合优化重要 atom coverage、complementarity 和 redundancy；
2. 提出 QEC 作为 selector structure 到 verifier input 的轻量接口，并通过 shortcut controls 分离 cue 与 evidence 的真实贡献；
3. 在 verdict、evidence sufficiency、robustness、cross-verifier transfer 和 efficiency 上进行联合评估。

其中 QEC map metadata 只有在消融后确有稳定收益且不存在 tag shortcut 时，才应上升为主贡献。

# 十三、执行优先级

截至 2026 年 6 月 19 日，AAAI-27 官方日程给出的 abstract deadline 是 7 月 21 日，full paper deadline 是 7 月 28 日。([AAAI][1])

建议按以下顺序执行：

**第一阶段：实验卫生与强基线**

* 删除所有 test-driven checkpoint 决策；
* 固定 validation protocol；
* 重跑 DeReC、KG-CRAFT-style、MMR、top-(B)；
* 统一 token budget。

**第二阶段：证明核心 selector**

* A4–A9 因果阶梯；
* map remove-one；
* graph edge remove-one；
* fixed vs adaptive token budget；
* ILP/beam oracle gap。

**第三阶段：排除 shortcut**

* tag-only；
* shuffled relation；
* wrong cue；
* qec_map without relation；
* evidence order shuffle。

**第四阶段：增强可信度**

* sufficiency/necessity；
* distractor robustness；
* cross-verifier；
* 人工 map 子集；
* 外部数据 transfer。

## 最终结论

新版已经修复了旧版最明显的两个问题：selector 不再只是 P1/P2/P3 规则 cascade，graph/evidence-map 信息也可以通过 QEC 进入 verifier。 

但当前版本直接投稿 AAAI 的风险仍然偏高，决定性问题不是再增加一个模块，而是证明：

1. 它与 KG-CRAFT、QACheck、GraphCheck、Minimal Evidence Group 等工作的本质区别；
2. graph 和 atom selection 在相同 verifier、相同 candidate pool、相同 token budget 下确实产生独立增益；
3. `qec_map` 的效果不是 relation pseudo-label shortcut；
4. 所选 evidence 真正满足 sufficiency、necessity 和 non-redundancy；
5. 所有 checkpoint 和 dataset-specific policy 均未受到 test 结果影响；
6. 与强方法相比，AA-QEC 至少在性能、证据可追踪性或计算成本中的一个维度形成明确 Pareto 优势。

在论文结构上，应把 **token-budgeted atom-aligned selector** 作为唯一主方法，把 ABC 作为 evidence-unit component，把 `qec_min/qec_map` 作为 rendering ablation。这样比将整条 pipeline 的每一个模块都宣称为创新更容易通过 novelty 和 soundness 审查。

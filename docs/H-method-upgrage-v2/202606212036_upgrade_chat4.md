## 结论

**选 Atom。**

更准确地说，使用 **decontextualized Atomic Verification Unit（原子核查单元）** 作为整条方法链唯一的 canonical anchor。Question 可以保留为由 Atom 一对一派生的检索表达，但不要再保留独立的 QD 分解结果、Question ID 或 Question–Atom 对齐过程。

你当前的问题本质上来自“双锚点”：

[
c\rightarrow Q\rightarrow \text{retrieval},
\qquad
c\rightarrow A\rightarrow \text{map/selector}.
]

QD 决定候选池，Atom 决定 evidence coverage，但二者可能出现一对多、多对一和语义错位。当前两份方案中，QD 位于检索扩池阶段，而 Atom 位于 evidence-map 和 selector 阶段，这正是需要消除的结构性冗余。 

重构后应统一为：

[
c\rightarrow A
\rightarrow \text{Atom-conditioned Retrieval}
\rightarrow \text{Atom–Evidence Map}
\rightarrow \text{Atom-aware Selector}
\rightarrow \text{Verifier}.
]

---

## 为什么不建议以 Question 为核心锚点

Question 比较适合作为**检索接口或交互式推理步骤**，不适合作为你的 selector 和证据图的基本语义单元。

### 1. Question 本身没有可判定的真假值

Evidence 与 Atom 之间可以直接定义：

[
r(e,a)\in
{\text{support},\text{refute},\text{qualify},\text{insufficient}}.
]

但 Evidence 与 Question 之间通常只能定义：

[
r(e,q)\in
{\text{relevant},\text{answerable},\text{partially-answerable}}.
]

例如：

```text
Question:
How much money did the government spend?

Evidence:
The government spent $3 billion.
```

这条 evidence 可以回答问题，但它究竟支持还是反驳原 claim，还取决于 claim 中声称的数值。

因此，Question 路径实际上需要增加一个中间变量：

[
c
\rightarrow q_i
\rightarrow e
\rightarrow \hat{ans}_i
\rightarrow \operatorname{Compare}(\hat{ans}_i,c)
\rightarrow y.
]

Atom 路径则可以直接写成：

[
c
\rightarrow a_i
\rightarrow e
\rightarrow r(e,a_i)
\rightarrow y.
]

Question 方案额外引入：

* answer extraction error；
* answer normalization error；
* answer–claim comparison error；
* yes/no question polarity bias；
* question presupposition错误；
* 多个答案形式不一致。

如果你把整个过程定义为 QA，就必须真正生成和验证中间 Answer。仅把 evidence text 称为 Answer，在概念上不够严谨，因为 evidence 可能只是部分证据、背景、反证或冲突信息。

QACheck 的 Question 路线之所以成立，是因为它明确包含 Question Generator、QA Model、QA Validator 和最终 Reasoner，属于真正的多步 QA 验证系统，而不是单纯 evidence subset selection。

---

## Atom 与你当前 selector 的目标天然一致

你的 selector 要优化的是：

* claim component coverage；
* important component coverage；
* evidence directness；
* complementarity；
* redundancy；
* conflict；
* evidence sufficiency。

这些目标都需要一个**有真值条件的命题单元**。

可以直接定义：

[
\operatorname{Coverage}(S)
==========================

\sum_{a_i\in A}
w_i
\max_{e\in S}
q(e,a_i),
]

其中：

[
q(e,a_i)
========

P(e\text{ directly supports/refutes/qualifies }a_i).
]

如果换成 Question，coverage 只能变成：

[
\sum_{q_i\in Q}
\mathbf 1[\exists e\in S:e\text{ answers }q_i],
]

它保证的是“问题被回答”，并不保证：

* 原 claim 的相应成分被正确核查；
* evidence 对该成分的 stance 已确定；
* 问题答案足以推导原 claim；
* 数值、时间、否定和比较关系被保留。

因此，**Atom 更适合做 selector 的集合覆盖基本单元，也更适合定义最小性、充分性和非冗余性**。Minimal Evidence Group 一类工作的形式化也是围绕 evidence 是否共同蕴含一个 claim，而不是围绕是否回答一组问题。

---

## Question 的检索优势如何保留

Question 的主要优势确实在检索：疑问形式通常会明确检索意图、未知槽位和关键关系。

但这不意味着要保留独立 QD。可以采用：

> **Atom 是唯一语义锚点；Question 只是 Atom 的 retrieval rendering。**

对每个 Atom (a_i)，构造一个一对一检索视图：

[
\rho(a_i)
=========

{
\text{proposition},
\text{keywords},
\text{entity–predicate slots},
\text{optional interrogative paraphrase}
}.
]

例如原 claim：

```text
Richard Grenell claimed that Adam Schiff voted to send
$100 billion in aid to foreign countries.
```

统一 Atom：

```text
a1:
Adam Schiff voted to allocate $100 billion in aid
to foreign countries.
```

它的检索视图可以是：

```text
proposition:
Adam Schiff voted to allocate $100 billion in foreign aid.

keywords:
Adam Schiff, vote, $100 billion, foreign aid

query rendering:
What amount of foreign aid did Adam Schiff vote to allocate?
```

关键点是：

* 三种表示都使用同一个 `atom_id=a1`；
* 不再单独生成 (Q={q_1,\ldots,q_m})；
* 不存在 Question–Atom alignment；
* selector 只基于 Atom；
* Question rendering 不进入图节点；
* Question rendering 不参与最终 coverage 计算。

FACT5 采用的实际上也是“先产生 atomic claims，再为每个 atomic claim 生成 question/query”的层级关系，说明 Question 更适合被视为 Atom 的检索接口，而不是与 Atom 平级的第二套语义分解。

## 推荐的新方法结构

### 1. 统一分解

[
A=\operatorname{Atomize}(c)
={a_1,\ldots,a_m}.
]

每个 Atom 建议至少包含：

```text
atom_id
proposition
importance
claim_span
entity_slots
predicate
arguments
temporal_constraint
numeric_constraint
negation
modality
attribution
dependencies
```

例如：

```json
{
  "atom_id": "A2",
  "proposition": "Adam Schiff voted to allocate $100 billion in foreign aid.",
  "importance": 1.0,
  "predicate": "vote_to_allocate",
  "arguments": {
    "actor": "Adam Schiff",
    "amount": "$100 billion",
    "purpose": "foreign aid"
  },
  "negation": false,
  "dependencies": []
}
```

### 2. Atom-conditioned retrieval

[
C_i=\operatorname{Retrieve}(\rho(a_i),U).
]

最终候选池：

[
C=
\operatorname{Merge}
\left(
C_{\rm global},
C_1,\ldots,C_m
\right).
]

其中 (C_{\rm global}) 可以保留原始 claim retrieval，用于防止 Atom 分解漏项；但它只是 global recall route，不是另一套分解锚点。

合并时保留：

```text
matched_atom_ids
per_atom_rank
per_atom_score
atom_hit_count
global_claim_score
```

原来的 `qd_question_hit_count` 可以直接改为：

```text
atom_route_hit_count
```

### 3. Atom–Evidence Map

对每个 ((a_i,e_j)) 标注：

[
M_{ij}
======

{
\operatorname{relation},
\operatorname{directness},
\operatorname{confidence},
\operatorname{keyspan}
}.
]

关系应是 atom-relative 的：

```text
support
refute
qualify
insufficient
background
```

不要只给一条 evidence 一个全局 relation，因为一条 evidence 可能：

* 支持 (a_1)；
* 限定 (a_2)；
* 与 (a_3) 无关。

因此 evidence map 最好从 evidence-level annotation 改成 pair-level annotation：

```text
(evidence_id, atom_id, relation, directness, confidence)
```

### 4. Selector

[
E^*
===

\arg\max_{S:\operatorname{TokLen}(S)\le B}
F(S;A,G).
]

其中：

[
F(S)
====

\lambda_{\rm cov}
\sum_i w_i\max_{e\in S}q(e,a_i)
+
\lambda_{\rm comp}F_{\rm complement}(S)
+
\lambda_{\rm ret}F_{\rm retrieval}(S)
-------------------------------------

## \lambda_{\rm dup}F_{\rm duplicate}(S)

\lambda_{\rm bg}F_{\rm background}(S).
]

这样初始检索、map、graph 和 selector 全部围绕同一套 `atom_id` 工作。

### 5. Verifier 输入

不再采用：

```text
Question:
...

Answer:
<evidence>
```

建议采用：

```text
Atomic verification unit A1:
Adam Schiff voted to allocate $100 billion in foreign aid.

Evidence:
[1] ...
[2] ...
```

或者更紧凑地：

```text
Check:
Adam Schiff voted to allocate $100 billion in foreign aid.

Evidence:
[1] ...
[2] ...
```

这里的 `Check` 是陈述句，不是疑问句。

如果希望 verifier 显式做中间判断，可以让其内部预测：

[
z_i\in
{\text{supported},\text{refuted},
\text{qualified},\text{insufficient}},
]

然后再聚合为最终六分类，而不是生成开放式 QA Answer。

## 不要追求“最小到不能再分”的 Atom

选择 Atom 不等于无限细分。

近期研究已经显示：

* decomposition 可能带来遗漏、错误拆分和上下文丢失；
* 最优分解粒度取决于 downstream verifier；
* 过度 atomic 可能损害检索和最终判断；
* decomposer 与 verifier 之间的 granularity alignment 很重要。

因此，建议定义的不是语言学意义上的绝对最小事实，而是：

> **最小的、能够独立检索证据并独立确定事实关系的核查单元。**

一个合格 Atom 应满足：

1. 有明确真值条件；
2. 脱离原句后仍可理解；
3. 保留时间、数量、否定、模态、归因和比较范围；
4. 可以独立检索 evidence；
5. 可以独立标注 support/refute/qualify；
6. 不拆开必须联合判断的谓词和参数。

例如：

```text
错误拆分：
A1: Adam Schiff voted.
A2: The amount was $100 billion.
A3: The money was foreign aid.
```

这些 fragment 单独都无法表达原 claim 的关键关系。

更好的 Atom 是：

```text
A1:
Adam Schiff voted to allocate $100 billion in foreign aid.
```

必要时，再产生用于支撑计算的 dependency atoms：

```text
A1.1: Adam Schiff voted for bill X.
A1.2: Bill X allocated amount Y to foreign aid.
A1 depends on A1.1 and A1.2.
```

## 两种方案的最终比较

| 维度                   | Question anchor        | Atom anchor                             |
| -------------------- | ---------------------- | --------------------------------------- |
| 检索表达能力               | 较强                     | 可通过 query rendering 补足                  |
| 是否具有真值条件             | 否                      | 是                                       |
| support/refute 标注    | 间接                     | 直接                                      |
| selector coverage    | 回答问题的覆盖                | claim component 的覆盖                     |
| evidence sufficiency | 难定义                    | 易定义                                     |
| graph 节点语义           | 较弱                     | 清晰                                      |
| 冲突证据建模               | 需先生成答案                 | 可直接建模 relation                          |
| 六分类 verdict 聚合       | 间接                     | 自然                                      |
| 中间误差数量               | 较多                     | 较少                                      |
| 与当前方法匹配度             | 一般                     | 高                                       |
| 论文定位                 | QA-style fact-checking | evidence selection / claim verification |

## 建议保留的确认性消融

尽管架构上建议直接选 Atom，实验中仍应保留三个版本：

[
\text{Question-only}
]

[
\text{Atom-only}
]

[
\text{Atom + 1:1 query rendering}.
]

重点比较：

* candidate Important-Atom Recall@token-budget；
* evidence–anchor alignment F1；
* background ratio；
* selected evidence redundancy；
* final Macro-F1；
* average input tokens；
* decomposition failure rate。

预期最合理的主方法应是：

[
\boxed{\text{Atom + 1:1 query rendering}}
]

其中论文层面的 canonical anchor 仍然只有 Atom。

一句话概括新的方法逻辑：

> **Decompose the claim into verifiable atomic propositions, retrieve evidence through atom-conditioned query views, and select a compact evidence set that collectively resolves the atomic propositions.**

因此，不建议把整个方法重构为 QA 回答过程；应重构为 **Atom-centered evidence resolution process**。Question 只作为检索视图存在，而不再是方法中的独立语义对象。

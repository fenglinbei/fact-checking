现在可以基本排除 evaluator/tokenization mismatch。诊断结果更符合一种特定模式：**test 上的证据链更容易被 verifier 解读为“不完全支持、存在限定或相互混合”，从而大量向 `half-true` 收缩；这不是全面性的证据失效。**

### 从结果中可以确定什么

观察到的 Macro-F1 gap 为 3.66 个百分点，但独立 bootstrap 的 95% CI 为 ([-0.28, 7.71]) 个百分点，仍包含 0。因此，单次训练尚不足以断言这是稳定的总体分布差异。不过，test 分数只位于 label-matched validation bootstrap 分布的 1.27% 分位，说明**标签比例差异无法解释主要 gap**，更可能是类条件分布：

[
P(x_{\text{claim}},x_{\text{evidence}},x_{\text{chain}}\mid y)
]

发生了变化。

更关键的是错误结构：

* `pants-fire`、`barely-true`、`mostly-true` 三类贡献了约 **84.3%** 的总 Macro-F1 gap；
* `false` 几乎不变，`true` 甚至略有提高；
* `half-true` 的预测比例从 22.2% 上升到 26.3%，增加 4.1 个百分点；
* `barely-true` 的预测比例下降约 3.0 个百分点；
* test 中：

  * `false → half-true` 增加约 8.8 个百分点；
  * `barely-true → half-true` 增加约 4.0 个百分点；
  * `mostly-true → half-true` 增加约 9.0 个百分点；
* severe error 没有增加：`abs(error)>=3` 反而从 9.97% 降至 9.67%；
* ordinal MAE 只从 1.002 增至 1.060。

所以这不像“test 上完全找错了证据”，而更像：

> **证据仍然大体相关，但 test 证据链表现得更模糊、更混合、更不直接，导致相邻等级边界失稳，并以 half-true 作为 uncertainty sink。**

`pants-fire` 可能是另一类问题：其 precision 从 68.1% 降到 53.3%，下降明显大于 recall，比较像 test 中极端虚假声明的语言模式、speaker/topic 或 evidence profile 与 validation 不同。

## 当前最值得怀疑的仍然是 selector，但不是“总分计算错误”

当前 selector 强制 `adaptive5_10`，默认目标 coverage 为 0.80，使用绝对 marginal-gain 阈值 0.10，并为 complements、corroborates、conditional tension 和 bridge context 提供正向奖励。其权重中 complements 为 0.18、corroborates 为 0.14、conditional tension 为 0.14、bridge 为 0.07，同时至少选择 5 条证据。([GitHub][1])

这些设计在 validation 上可能选出“充分且互补”的链，但在 test 上，如果 evidence map 更频繁地产生：

* `qualify` / `mixed`；
* `partial` / `context`；
* tension edges；
* 长 ABC chunk；
* 同一 atom 的多条不同立场证据；

那么 selector 会把“更多不确定性”带入 prompt。由于 `qec_min` 不显示显式 relation 标签，verifier 只能从原始文本判断，最自然的结果就是向 `half-true` 收缩。

因此，现阶段更精确的假设是：

[
\text{相同 selector objective}
+
\text{不同 graph/map feature distribution}
\Rightarrow
\text{不同 chain semantics}
\Rightarrow
\text{half-true centralization}.
]

这不要求 selector 代码有 bug。问题可能是它的 objective 对 graph density、map relation 和 evidence directness 的分布变化不够稳健。

# 下一步首先做的诊断

## 1. 比较“实际截断暴露”，而不仅是截断策略

val/test 使用相同 1024-token 截断策略，只能说明 evaluator contract 一致，不能说明二者受到的截断程度相同。

需要分别统计：

* prompt 截断率；
* 截断前 token 数；
* 实际保留下来的 evidence step 数；
* 被截断的是第几条 evidence；
* 被截断 evidence 的 relation/directness；
* claim 是否完整保留；
* `Check:` cue 是否保留但对应 evidence 被截掉；
* 各 gold label 下的截断率。

尤其要检查：

[

]

与 validation 是否不同。

如果相同截断策略下，test 的 ABC chunks 更长，那么 adaptive5–10 可能使 test 更频繁地丢失后部 evidence，或只保留 evidence 的一部分。这仍然属于 evidence-distribution shift。

### 类条件漂移

不要只比较总体 val/test，而要比较：

[

\quad\text{与}\quad
P(f\mid y,\text{test}).
]

重点检查 `barely-true`、`mostly-true` 和 `pants-fire`。

每个连续特征报告：

* standardized mean difference；
* KS statistic；
* 中位数与四分位数；
* 按特征四分位分组的 Macro-F1。

每个离散特征报告：

* stop reason 分布；
* relation/directness 分布；
* selected-count 分布。

### Split discriminator

使用这些 selector/chain 特征训练一个简单的 val-vs-test logistic regression，并在每个 gold label 内分别训练。

解释方式：

* 总体 AUC 高、类条件 AUC 也高：真实的 selector-output shift；
* claim 特征 AUC 低、chain 特征 AUC 高：selector 放大了原始差异；
* `tension/context/selected_tokens` 是主要特征：当前 objective 很可能导致 test evidence ambiguity；
* speaker/topic/source 特征最重要：更接近数据分组差异。

经验上无需追求某个固定阈值，但若类条件 AUC 已达到约 0.65–0.70，通常已经足以说明两组 chain 分布可区分。

### Error regression

训练一个预测 `correct/incorrect` 的轻量模型，并加入：

[
\text{split}\times \text{feature}
]

交互项。例如：

[
\operatorname{Error}
\sim
\text{split}
+
\text{context ratio}
+
\text{split}\times\text{context ratio}.
]

如果 `split × context_ratio` 或 `split × tension_count` 显著，说明同样的 graph 特征在 test 上破坏性更强。

# 最有价值的 frozen-checkpoint 反事实实验

在重训前，直接用当前 checkpoint 对同一 val/test 样本生成几种输入。这样可以快速定位 selector 是否是主要原因。

| 变体 | 输入                                            |
| -- | --------------------------------------------- |
| C0 | 当前 adaptive5–10 chain                         |
| C1 | 只保留当前 chain 的前 3 步                            |
| C2 | 只保留 direct/partial 且覆盖 atom 的 evidence，最多 5 条 |
| C3 | C0 去掉 context/background/irrelevant           |
| C4 | C0 去掉只因 tension/bridge 被加入的 evidence          |
| C5 | 固定 retrieval top-5                            |
| C6 | selected set 不变，但按 atom 分组排列                  |
| C7 | claim-only                                    |

重点不是只看总 F1，而是看：

[
\Delta_{\text{test}}-\Delta_{\text{val}}
]

以及 `half-true` 预测率。

最关键的判据：

* C2/C3/C4 在 test 提升明显，而 validation 几乎不变：selector 引入的 ambiguity 是主要原因；
* C1 优于 C0：至少 5 条 evidence 的硬下限过高；
* C5 gap 明显小于 C0：复杂 graph score 在放大 split shift；
* 所有 evidence 变体的 gap 都类似：问题更可能在 claim/speaker/topic 分布或 verifier；
* claim-only gap 也很大：先处理数据 group shift，而不是 selector。

由于这些输入与训练时 prompt 分布不同，它们不能直接作为最终结果，但非常适合进行因果定位。

# 推荐的 selector 改造：Direct-Core Relative Chain

我不建议继续调十几个现有 objective weights。更稳妥的是将 selector 改成：

> **先解析 atom，图关系只能辅助，不允许单独驱动证据加入。**

建议将 `adaptive5_10` 改成 `adaptive2_6` 或 `adaptive3_7`，并取消“必须补足 5 条”的规则。

## 1. 定义 atom resolution

对 evidence (e) 和 atom (a)：

[
q(e,a)
======

\mathbf 1[e\text{ covers }a]
\cdot d(e,a)
\cdot c(e,a),
]

其中初始 directness 可以设为：

[
d(e,a)=
\begin{cases}
1.0,&\text{direct}\
0.60,&\text{partial}\
0,&\text{context/none}.
\end{cases}
]

atom resolution：

[
R_a(S)
======

1-\prod_{e\in S}(1-q(e,a)).
]

整体 resolution：

[
R(S)
====

\frac{\sum_a w_aR_a(S)}
{\sum_a w_a}.
]

这样，同一 atom 的第二条、第三条证据收益自然递减，而不是依靠多个手工 penalty 相互抵消。

## 2. 简化 marginal gain

[
\Delta(e\mid S)
===============

\Delta R(e\mid S)
+
\alpha C_{\mathrm{independent}}(e,S)
+
\beta C_{\mathrm{valid-conflict}}(e,S)
--------------------------------------

\gamma\operatorname{TokenCost}(e).
]

其中：

* independent corroboration 只在不同 source、同一 atom、同一 stance 时奖励一次；
* valid conflict 必须满足严格 gate；
* complements、key-span、map-quality 不再分别重复加权；
* background/context 不产生 atom resolution。

建议初始范围：

[
\alpha\in{0.05,0.10},
\qquad
\beta\in{0,0.03,0.06}.
]

当前的 conditional tension 权重为 0.14，和 corroboration 相同量级，我认为在目前的错误结构下偏高。([GitHub][1])

## 3. 对 tension 使用严格 gate

只有同时满足下列条件时 tension 才能产生正收益：

```text
两条 evidence 覆盖同一个 atom
两条 evidence 都是 direct 或 partial
两者 stance 相反或明确不一致
来自不同 source
不是 duplicate/paraphrase
冲突 evidence 能改变 atom 的最终状态
```

否则 tension reward 为 0，而不是默认正奖励。

这可以防止：

```text
范围差异
时间差异
背景描述差异
同源措辞差异
弱 qualify 文本
```

被错误地当作有价值冲突加入 chain。

## 4. bridge/context 改为受限操作

context evidence 只能在以下条件下加入：

```text
已有一条 direct/partial evidence；
context 与该 evidence 覆盖同一 atom；
不加入 context 时存在明确实体、时间或定义缺失；
每条 chain 最多 1 条 context evidence。
```

bridge 不得用于满足最小 chain 长度，也不能独立把 atom 标记为 resolved。

## 5. 使用硬约束

```text
每个 duplicate group 最多 1 条；
每个 source 最多 2 条；
每个 atom 最多 2 条，除非存在有效冲突；
context evidence 最多 1 条；
总 evidence 使用 verifier tokenizer 计数；
不允许 selector 为满足 min_top_k 强制补充低收益证据。
```

## 6. 改成相对停止

当前绝对 threshold 0.10 对不同 graph density 和 atom 数不稳定。建议：

[
\frac{\Delta_t^*}
{\Delta_1^*+\epsilon}
<\rho,
]

其中：

[
\rho\in{0.08,0.12,0.16}.
]

停止条件：

[
R_{\text{core}}(S)\ge\tau
\quad\land\quad
\frac{\Delta_t^*}{\Delta_1^*+\epsilon}<\rho.
]

同时，如果没有 candidate 能增加 atom resolution，也立即停止。

## 7. 使用 token budget

不要再以 5–10 条作为主要预算。应令：

[
B_{\mathrm{evidence}}
=====================

## 1024

## \operatorname{TokLen}(\text{instruction+claim+labels})

B_{\mathrm{safety}}.
]

例如保留 64–96 token safety margin。每个样本根据 claim 长度获得实际 evidence budget。这样不会因为 test ABC chunks 更长而产生不同的有效上下文。

---

# 为什么这个改造更可能保留 validation

当前结果不是说明前几条核心 evidence 无效，而是后续 evidence 可能增加模糊性。Direct-Core selector 会保留：

* 主要 direct evidence；
* 新 atom evidence；
* 必要的独立 corroboration；
* 真正有效的冲突证据。

它主要删除：

* 为满足 `min_top_k=5` 加入的 evidence；
* context/background；
* 对同一 atom 的重复证据；
* 只因图上存在 edge 而加入、但不能改变 atom resolution 的证据。

因此它比降低模型容量、提高 dropout 或大幅修改 loss 更有可能满足：

[
F1_{\mathrm{val,new}}
\ge
F1_{\mathrm{val,baseline}}-0.002
]

同时提高 test 泛化。

# 第二优先级：Chain Perturbation Consistency Training

如果 frozen counterfactual 证明 compressed/direct-core chain 在 test 上更稳，下一步不要只用新 selector 重训。建议同时让 verifier 对合理的 chain 变化保持稳定。

对每个训练样本构造：

* (z_0)：标准 selector chain；
* (z_1)：direct-core compressed chain；
* (z_2)：将一条 evidence 替换为覆盖同一 atom 的次优 evidence；
* (z_3)：去掉一条低 marginal-gain 的 context/corroboration evidence。

损失：

[
\mathcal L
==========

\operatorname{CE}(p_0,y)
+
\alpha\frac{1}{K}\sum_{k=1}^{K}\operatorname{CE}(p_k,y)
+
\beta\frac{1}{K}\sum_{k=1}^{K}
\operatorname{JS}(p_0,p_k).
]

建议先测试：

[
\alpha\in{0.25,0.5},
\qquad
\beta\in{0.05,0.1}.
]

标准 chain 的 CE 始终保留，因此它不是用鲁棒性替代 nominal performance，而是在不放弃原 validation 分布的情况下，限制模型依赖：

* 固定 evidence 数量；
* 固定顺序；
* 某条特定 evidence；
* 某种固定 selector pattern。

还可以给 `Check:` cue 做 15%–20% dropout，让部分训练样本只显示 evidence text，防止 verifier 过度依赖 QEC cue 的表述分布。

---

# 第三优先级：检查边界校准，而不是立即加 ordinal loss

当前需要先保存六个 label 的原始 logits/probabilities。每个样本至少输出：

```text
logit_A ... logit_F
prob_A ... prob_F
entropy
top1_margin
expected_label_rank
```

重点分析相邻边界：

[
m_{PF,F}=z_{PF}-z_F
]

[
m_{F,BT}=z_F-z_{BT}
]

[
m_{BT,HT}=z_{BT}-z_{HT}
]

[
m_{HT,MT}=z_{HT}-z_{MT}
]

[
m_{MT,T}=z_{MT}-z_T.
]

根据当前 confusion matrix，最可能发生漂移的是：

[
m_{BT,HT}
\quad\text{和}\quad
m_{MT,HT}.
]

如果 test 的 entropy 上升、top-1 margin 下降，并且主要集中在 BT/HT/MT，则说明 verifier 的相邻决策边界没有适应 evidence-chain shift。

当前代码提供的 ordinal loss 是 softmax 下的 expected absolute-rank distance。([GitHub][2])

目前不建议把它作为第一项修改。你的主要问题已经是向中间类收缩；在 label noise 和不确定证据下，距离型正则可能进一步平滑概率分布。更合适的顺序是：

1. 先减少 ambiguous chain；
2. 再分析 logits；
3. 若仍存在相邻边界漂移，再试 cumulative ordinal thresholds 或相邻 margin loss。

# 训练随机性还没有被排除

当前 trainer 默认 seed 为 42，除非 resolved config 覆盖。([GitHub][2])

现有 bootstrap 只重采样数据样本，没有覆盖：

* LoRA 初始化；
* batch 顺序；
* dropout；
* optimizer trajectory；
* checkpoint trajectory。

因此建议至少对当前 baseline 跑 3 个 seeds，先得到：

[
\mu_{\mathrm{val}},
\quad
\sigma_{\mathrm{val}},
\quad
\mu_{\mathrm{test}},
\quad
\sigma_{\mathrm{test}},
\quad
\mu_{\mathrm{gap}}.
]

如果三个 seed 的 test 都稳定低 2.5–4 点，才能把它认定为较稳定的 split shift。如果不同 seed 的 gap 在 0–5 点间波动，则应优先使用 logit ensemble，而不是过度修改 selector。

低成本方案是对 one-SE 范围内 3 个 checkpoint 做 logit averaging：

[
z_{\mathrm{ens}}
================

\frac{1}{3}
\sum_{j=1}^{3}z_j.
]

模型选择和 ensemble 成员仍然只由 validation 或内部 CV 决定。

# 需要审计 class weights 与 tau，但它们不是当前第一嫌疑

当前脚本设置：

```text
pants-fire = 1.2
false = 1.0
barely-true = 1.5
half-true = 1.0
mostly-true = 1.0
true = 1.8
```

trainer 将这些权重作为逐样本 weighted CE；脚本还单独运行默认 (\tau=0.75) 的 logit-adjust evaluation。([GitHub][3])

应先确认上传诊断对应的是：

```text
原始 label-token prediction
```

还是：

```text
tau=0.75 adjusted prediction
```

从文件路径看，更像未调整的基础路径，但应以实际 artifact metadata 为准。

随后只在内部 CV 上比较：

| 实验 | class weights | logit adjustment          |
| -- | ------------- | ------------------------- |
| W0 | 无             | 无                         |
| W1 | 当前 weights    | 无                         |
| W2 | 无             | validation-calibrated tau |
| W3 | 当前 weights    | validation-calibrated tau |

不要默认把 weighted CE 和 prior adjustment 同时作为主配置，因为二者都在修改类别边界。

当前错误结构中：

* `true` 没有退化；
* `false` 基本稳定；
* `barely-true` 即使有 1.5 的权重仍显著退化。

这说明 class weight 本身不像根因，但可能放大了某些边界对 evidence shift 的敏感性。

# 检查 validation 是否因 train overlap 而偏乐观

还需要比较每个 val/test 样本与训练集的：

* 最近 claim embedding similarity；
* claim lexical overlap；
* selected evidence canonical-text overlap；
* speaker 是否出现在 train；
* subject/topic 是否出现在 train；
* report domain/source 是否出现在 train；
* 时间区间；
* claim template；
* atom-type composition。

建议特别报告：

[
F1
\quad\text{vs}\quad
\max_{x_{\mathrm{train}}}\operatorname{sim}(x,x_{\mathrm{train}}).
]

如果 validation 有更多高相似 train neighbors，而 test 更多低相似样本，那么 3–4 点 gap 可能主要是 official validation 偏乐观。此时单纯修改 selector 很难完全消除，应使用 group-aware internal validation。

# 如何在不损失 official validation 的情况下选泛化配置

不要直接最小化：

[
F1_{\mathrm{val}}-F1_{\mathrm{test}}.
]

因为降低 validation 就能机械缩小 gap。

在 training set 内构造 5 个 pseudo-domain folds，优先按以下 group 划分：

```text
speaker
claim embedding cluster
subject/topic
report source/domain
evidence-chain complexity
```

同时保持标签近似分层。

候选配置必须满足 official validation 非劣约束：

[
F1_{\mathrm{official\ val}}
\ge
0.379843-0.002
==============

0.377843.
]

在满足约束的配置中，最大化：

[
S_{\mathrm{robust}}
===================

## \overline{F1}_{\mathrm{fold}}

0.5\operatorname{Std}(F1_{\mathrm{fold}}),
]

或者直接最大化 worst-fold Macro-F1。

这样，“不损失 val”是硬约束，“提高泛化”由 internal pseudo-domain stability 衡量，而不是继续观察 test 后调参。

# 建议的最小实验顺序

第一轮不重训：

1. 当前 chain；
2. first-3 chain；
3. direct/partial core-only；
4. 去掉 context/bridge；
5. 去掉 tension-only additions；
6. fixed retrieval top-5；
7. 输出六类 logits 和 selector trace features。

第二轮只重训最有希望的三组：

| ID | 方法                                                         |
| -- | ---------------------------------------------------------- |
| R0 | 当前 adaptive5–10                                            |
| R1 | Direct-Core adaptive2–6 + token budget + relative stopping |
| R2 | R1 + chain perturbation consistency                        |

第三轮：

* 当前 baseline 3 seeds；

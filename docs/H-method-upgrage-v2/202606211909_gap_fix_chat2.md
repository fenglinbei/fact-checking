这两个结果基本排除了“checkpoint 选择策略”是主要原因。下一步不应直接假定是数据分布差异；当前仓库里还有一个优先级更高的风险：**validation 与 test 可能并没有经过完全相同的输入截断和 label scoring 路径。**

## 1. 先排除 evaluator/input contract mismatch

当前 `LabelTokenDataset` 在输入超过 `max_length` 且未启用 prefix preservation 时，会执行：

```python
input_ids = input_ids[-max_length:]
```

也就是从左侧截断。这可能删除位于 prompt 前部的 claim 和前几条证据，只保留后部证据及 `Label:` prefix。与此同时，现有 prompt statistics 中的 `was_truncated` 主要记录 prompt 构造阶段的 evidence truncation，不一定能发现 dataset tokenization 阶段发生的这次隐式截断。

test 的 API 推理路径则直接提交 `sample.prompt`；虽然加载了 `max_length`，但当前路径没有据此做与训练一致的 token-level 截断。vLLM 的 `truncate_prompt_tokens` 默认也是 `None`，除非显式指定，否则不会复现 trainer 的左截断。([GitHub][1])

这会形成：

```text
train / trainer-val:
    最后 2048 tokens，可能删除 claim 和前部 chain

API-test:
    完整 prompt，或由 vLLM model context 决定
```

模型实际学习的是一种上下文分布，test 却给了另一种上下文分布。test 中增加的早期 evidence、background 或 claim token 不一定帮助模型，反而可能改变注意力模式和标签概率。

### 必须做的 parity test

对同一个 checkpoint、同一批 validation 样本，运行三次：

| 评估 | 输入与评分路径                                                      |
| -- | ------------------------------------------------------------ |
| P1 | 当前 trainer/HF validation evaluator                           |
| P2 | 当前 vLLM API evaluator                                        |
| P3 | vLLM API，但强制使用与 trainer 完全一致的 token IDs、截断和 prior correction |

记录：

```text
exact input token hash
input token count
actual truncation
six label logits/log-probabilities
prediction
```

要求：

```text
P1 与 P3 的输入 token IDs 100% 一致
prediction agreement 接近 100%
```

若 P1 与 P2 在同一个 validation set 上已经相差 1–3 个 Macro-F1 点，那么目前观察到的不是纯粹的 val/test distribution gap，而是 evaluator gap。

正式 test 最稳妥的做法是直接复用 trainer 的 evaluator，而不是另走一套 API scoring 逻辑。

### 推荐修复

不要保留隐式左截断。将它改成显式错误：

```python
input_ids = tokenizer(
    prompt + label_prefix,
    add_special_tokens=False,
).input_ids

if len(input_ids) > max_length:
    raise RuntimeError(
        f"Prompt overflow: {len(input_ids)} > {max_length}"
    )
```

然后在 evidence-chain 构造阶段保证：

[
\operatorname{TokLen}(\text{fixed prompt})
+
\operatorname{TokLen}(E^*)
+
\operatorname{TokLen}(\text{label prefix})
\leq L_{\max}.
]

即以 tokenizer 的真实 token 数裁剪 chain，而不是在模型输入阶段截断。必须始终保留：

```text
instruction
claim
每个 chain step 的 Check 字段
关键 evidence
Label:
```

train、validation、test 共用同一个 prompt encoder 函数。

另一个需要对齐的是 logit adjustment。trainer 中明确执行了：

[
z'*y=z_y-\tau\log p*{\mathrm{train}}(y),
]

但 API prompt-logprob 路径主要依赖 backend 的 `logit_bias`，没有在 Python 侧显式保证相同的变换。建议读取六个 raw label log-probability 后统一执行：

```python
adjusted_scores = raw_scores - tau * np.log(train_priors)
prediction = adjusted_scores.argmax()
```

不要依赖 `logit_bias` 是否对 prompt logprobs 产生与 trainer 完全相同的效果。([GitHub][2])

## 2. 先确认 2.5–4 点 gap 有多少是统计波动

Macro-F1 对小类别非常敏感。先将 gap 分解为：

[
\Delta_{\mathrm{macro}}
=======================

\frac{1}{C}
\sum_{c=1}^{C}
\left(
F1^{\mathrm{val}}_c-F1^{\mathrm{test}}_c
\right).
]

需要报告：

```text
每类 precision / recall / F1
每类预测数量
confusion matrix
ordinal error distance
10,000 次 bootstrap 的 95% CI
```

判断方式：

* **recall 下降为主**：test 中该类的 evidence 更难召回或 selector 更容易漏证据；
* **precision 下降为主**：类别校准、标签先验或相邻类别决策边界发生变化；
* **只有一两个类下降**：不是整体 domain shift，应针对这些类分析 evidence pattern；
* **所有类同步下降**：更像输入协议、模型泛化或整体 evidence quality 差异。

我基于公开原始 LIAR valid/test TSV 做过一个快速检查：两个切分的标签分布总变差约为 0.049，属于较温和的 prior shift；但 `pants-fire` 数量分别只有约 116 和 92，因此单类 F1 的方差不可忽视。这个结论只能作为 ancestral LIAR split 的 sanity check，LIAR-RAW 增加了 raw reports，实际更可能发生的是 **evidence-side shift**，必须在你最终使用的 JSONL 上重新计算。LIAR-RAW 本身是在 LIAR/LIAR-PLUS 基础上增加 raw reports 的任务设置。([ACL Anthology][3])

还可以做一次 label-matched validation bootstrap：从 validation 中按 test 的每类样本数重采样，得到一组 validation Macro-F1 分布。这个实验只用于诊断，不能用来选择模型，因为它使用了 test 标签分布。

## 3. 把“数据分布差异”分解到四个层级

你的旧版和新版都不是单纯的 claim classifier。旧版已经通过 atom、evidence map、typed graph 和 5–10 条 rule-step evidence selection 构造输入；新版进一步使用 budgeted graph chain 和 QEC rendering。因此，selector 输出本身已经构成 verifier 的输入分布。 

建议为 train、validation 和 test 每个样本导出如下审计表：

| 层级                | 必须记录的变量                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| Claim             | label、claim tokens、atom 数、speaker/source/topic、时间、claim type                                            |
| Reports/Retrieval | report 数、report tokens、candidate 数、top score、score margin、QD hit count                                  |
| Map/Graph         | direct/partial/context 比例、map confidence、graph edge density、duplicate ratio、冲突边比例                       |
| Selector/Prompt   | selected count、selected tokens、atom coverage、source diversity、stop reason、prompt tokens、actual overflow |

然后做三类分析。

### 3.1 Split discriminator

使用上述特征训练一个简单的 validation-vs-test 二分类器，不使用 veracity label。

解释方式：

```text
claim features AUC ≈ 0.5，selector features AUC 较高
    → selector 放大了原始的小差异

claim features 和 selector features AUC 都高
    → 上游数据本身存在明显 domain shift

claim features AUC 高，但 selector features降低
    → selector 对 shift 有一定归一化作用
```

当前 test 只能用于事后定位，不能据此反复调权重。正式方法应在 training 内构造 pseudo-domains 复现这种 shift。

### 3.2 条件性能曲线

分别计算以下条件下的 validation/test F1：

```text
atom 数 = 1 / 2 / ≥3
selected tokens 四分位
report 数四分位
direct-evidence ratio
background ratio
graph density
prompt 是否超过 2048 tokens
stop reason
```

例如，如果 gap 几乎全部来自 `selected_tokens` 最高四分位，那么首先应修复上下文长度和 selector budget，而不是修改分类 loss。

### 3.3 反事实定位

在完全相同 evaluator 下比较：

| 输入                                    | 用途                         |
| ------------------------------------- | -------------------------- |
| claim-only                            | 测基础 dataset shift          |
| fixed rank top-B tokens               | 测无参数 retrieval baseline    |
| 当前 graph chain                        | 测 selector 是否放大 shift      |
| all top-N，按同一 token budget            | 测 selector 是否删除了 test 关键证据 |
| 当前 selected set + plain/QEC rendering | 测 prompt structure 是否过拟合   |

关键判断：

```text
claim-only 已有大 gap
    → verifier / label / claim distribution 问题

fixed top-B gap 小，graph chain gap 大
    → graph/map score 或 stopping rule 过拟合

all top-N gap 小，selected chain gap 大
    → selector 在 test 上发生 evidence omission

qec_min gap 小，qec_map gap 大
    → relation/directness tags 出现 shortcut 或 calibration shift
```

## 4. 当前 selector 中最需要修改的泛化风险

### 4.1 v0.7 graph selector：绝对阈值对 split 不稳定

当前实现使用固定的 coverage target 和绝对 gain threshold，例如 `target_coverage≈0.80`、`stop_gain≈0.10`，同时 graph relation utility 会随图密度累加。不同 split 中 atom 数、map confidence、edge density 或候选池规模略有变化，就可能改变 chain 长度与组成。([GitHub][4])

建议改成样本内相对停止：

[
\frac{\Delta F_t^{*}}
{\Delta F_1^{*}+\epsilon}
< \rho,
]

而不是：

[
\Delta F_t^{*}<0.10.
]

其中 (\rho) 只在 training 内部 folds 上选择。

同时：

* retrieval score 改为 candidate rank 或 percentile，而不是跨样本未校准的原始分数；
* graph edge utility 按 atom 或 edge type 归一化；
* 同一 atom 的 corroboration/complement reward 最多计算一次；
* duplicate、source count 和 token budget 改为硬约束；
* 不强制补足固定 evidence 数量。

### 4.2 如果当前运行的是 MREC/state-chain selector

current main 中还需要检查以下状态语义：

* `conflicted` 不应计为 resolved；
* `qualified` 不应与 direct support/refute 得到同等 resolution；
* context evidence 不应直接把 unresolved atom 更新为 supported/refuted；
* 一条覆盖多个 atoms 的 evidence 应更新所有合法 atoms，而非只更新最优的一个；
* fallback 必须排除已选 evidence 和 duplicate group，并遵守 token budget；
* token cost 必须使用 verifier tokenizer，而不是 whitespace word count。

按当前实现，`S/R/Q/C` 都可能进入 resolving states，context evidence 也可能触发 atom state transition，这会使 chain 是否达到停止条件高度依赖 map relation 分布。([GitHub][5])

建议使用如下 resolution value：

[
r(a)=
\begin{cases}
1.0,&\text{direct support/refute}\
0.7,&\text{partial support/refute}\
0.4,&\text{qualified}\
0,&\text{conflicted or unresolved}.
\end{cases}
]

停止条件改成：

```text
重要 atoms 达到 weighted resolution threshold
AND
不存在未处理的可信冲突
AND
没有候选产生有效状态转移
```

这样比“80% atoms 已处于某个非 U 状态”稳定得多。

## 5. 最值得优先尝试的泛化训练：chain perturbation consistency

如果 gap 确实主要来自 selector/evidence distribution shift，我会优先采用 **chain perturbation consistency training**，而不是继续调 selector 权重。

对每个训练样本构造：

```text
z0: 当前 selector 的标准 chain

z1: 删除一条低价值 context/corroboration evidence
z2: 用覆盖同一 atom 的次优 candidate 替换一条 evidence
z3: token budget 变化 ±20%
z4: 替换同源重复证据或轻微改变独立 steps 的顺序
```

所有 chain 都使用相同 gold label。损失为：

[
\mathcal L
==========

\operatorname{CE}(p_0,y)
+
\frac{\alpha}{K}\sum_{k=1}^{K}\operatorname{CE}(p_k,y)
+
\frac{\beta}{K}\sum_{k=1}^{K}
\operatorname{JS}(p_0,p_k).
]

其中 (p_0) 是标准 chain 的预测。

这一方案比只加噪声更适合当前问题，因为：

1. 标准 chain 仍然保留在训练目标中，因此不会主动牺牲 nominal validation performance；
2. 替换的是语义上等价或近似等价的 evidence chain；
3. consistency 项直接约束 verifier 不要依赖某条证据的固定位置、固定措辞或固定 selector pattern；
4. 它模拟的正是 val/test 之间可能出现的 retrieval、map 和 chain 组成差异。Consistency training 是成熟的鲁棒学习范式；GroupDRO 和 risk extrapolation 则可用于进一步控制不同环境间的性能方差。([NeurIPS Proceedings][6])

建议先搜索一个很小的范围：

```text
alpha ∈ {0.25, 0.5}
beta  ∈ {0.05, 0.1, 0.2}
每个样本 2 个 perturbations
```

不要一开始生成大量扰动，否则会改变训练任务本身。

## 6. 用 pseudo-domain validation 代替单一 validation peak

即使 official validation 没有明显问题，单一切分也不一定代表 test domain。建议在 training 内构造 5 个 group-aware folds：

```text
speaker/source 尽量不交叉
label 分层
report-count 和 prompt-length 分层
atom complexity 分层
```

配置选择不再只看一个 validation 峰值，而看：

[
S_{\mathrm{robust}}
===================

## \overline{F1}_{\mathrm{fold}}

\gamma\operatorname{Std}(F1_{\mathrm{fold}}).
]

为了满足“不明显损失 official val”，使用非劣约束：

[
F1_{\mathrm{official\ val}}
\ge
F1_{\mathrm{baseline\ val}}-0.002.
]

在满足该约束的配置中，选择：

```text
cross-fold mean 更高
cross-fold std 更低
worst-fold F1 更高
```

而不是选择 official validation 单点最高者。

训练 loss 也可以加入较弱的环境方差项：

[
\mathcal L_{\mathrm{robust}}
============================

\frac{1}{G}\sum_g\mathcal L_g
+
\lambda_{\mathrm{vrex}}
\operatorname{Var}_g(\mathcal L_g),
]

其中 group 可按：

```text
label × evidence-complexity
label × direct-evidence-ratio
label × prompt-length bucket
```

定义。先使用较小的 (\lambda)，并受上述 validation non-inferiority constraint 约束。

## 7. 推荐的执行顺序

| 阶段 | 实验                                     | 目的                          |
| -- | -------------------------------------- | --------------------------- |
| A1 | 同一 validation：trainer vs API           | 排除 evaluator mismatch       |
| A2 | 所有 split 统计真实 token overflow           | 排除隐藏截断                      |
| A3 | 显式统一 logit adjustment                  | 排除 scoring mismatch         |
| B1 | per-class F1 + bootstrap CI            | 确认 gap 来源和显著性               |
| B2 | claim/fixed-top-B/graph-chain 对照       | 定位 selector 是否放大 shift      |
| B3 | selector feature split discriminator   | 找出发生漂移的具体变量                 |
| C1 | relative stopping + rank normalization | 提高 selector scale stability |
| C2 | 修复 atom state semantics                | 防止错误提前停止                    |
| C3 | chain perturbation CE                  | 提高 evidence variation 鲁棒性   |
| C4 | chain perturbation + JS consistency    | 降低 verifier 对固定 chain 的依赖   |
| C5 | 3-seed logit ensemble                  | 降低剩余训练方差                    |

最重要的接受标准不是单纯“gap 变小”，因为降低 validation 也能机械地减小 gap。建议同时报告：

```text
validation Macro-F1
test Macro-F1
test − validation
5-fold mean / std
worst-fold Macro-F1
actual truncation rate
selector split-discriminator AUC
每类 F1
```

最终候选必须满足：

[
F1_{\mathrm{val}}
\ge F1_{\mathrm{baseline,val}}-0.002
]

并且至少在 cross-fold stability、test F1 或 worst-group F1 上有明确改善。

目前我会按以下优先级判断：

1. **先验证 train/val/test evaluator 与 tokenization 是否完全一致**；
2. **再确定 gap 是由哪几个类别和哪类 evidence 样本产生**；
3. **将固定 absolute selector score 改为 relative/rank-normalized state transition**；
4. **使用 nominal-chain-preserving consistency training**；
5. **用 group-aware internal CV 选择稳健配置，而非继续针对当前 test 调参**。

由于当前 test 已经被多次用于 checkpoint diagnostics，后续改动不应再依据该 test 的结果选择超参数。比较严谨的投稿做法是：用当前 test 仅完成一次根因分析，之后在 training 内的 pseudo-domains 上确定全部方案，冻结配置，再使用一个未查看的 holdout 或重新划定的 blind evaluation 做最终报告。
